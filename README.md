# 온라인 평가 시스템 (무료 · 개인 구글 계정)

학생은 **본인 구글 계정으로 로그인**하고, **반·번호를 한 번 등록**합니다. 교사가 **승인**하면 시험을 볼 수 있습니다.
**정답은 서버(DB)에만 있고 채점도 서버에서** 하기 때문에, 학생이 소스 보기를 해도 정답이 나오지 않습니다.

| 구성 | 쓰는 곳 | 비용 |
|---|---|---|
| 화면 (HTML) | GitHub Pages | 무료 |
| 로그인, DB, 채점 | Supabase (무료 요금제, 카드 등록 없음) | 무료 |
| 구글 로그인 키 | Google Cloud Console | 무료 |

```
exam-system/
├─ supabase/schema.sql   ← DB와 채점 함수 (Supabase에 한 번 실행)
└─ docs/                 ← GitHub Pages가 게시하는 폴더 (화면 파일)
   ├─ index.html         ← 학생 화면 (로그인 → 등록 → 응시 → 결과)
   ├─ teacher.html       ← 교사 화면 (학생 승인 / 시험·문항 / 결과·CSV)
   ├─ config.js          ← Supabase 주소와 키 (여기만 수정)
   ├─ api.js, style.css
```

> **먼저 둘러보기:** `config.js`가 비어 있으면 자동으로 **데모 모드**로 열립니다. 서버 없이 이 브라우저 안에서만 동작합니다.
> 학생 화면과 교사 화면을 오가며 등록 → 승인 → 응시 → 결과 흐름을 미리 볼 수 있습니다.

## 설치 (처음 한 번, 약 30분)

### 1. Supabase 프로젝트 만들기
1. https://supabase.com 에 가입하고 **New project**를 누릅니다. Region은 `Northeast Asia (Seoul)`, DB 비밀번호는 아무거나 길게 정합니다.
2. 왼쪽 **SQL Editor**를 엽니다.
3. `supabase/schema.sql` 전체를 붙여 넣습니다. **맨 아래 `teacher@gmail.com`을 본인 Gmail(소문자)로 바꾼 뒤** **Run**을 누릅니다.
   - 여러 번 실행해도 안전합니다. 기존 데이터는 지워지지 않습니다.

### 2. 구글 로그인 키 만들기 (Google Cloud Console)
1. https://console.cloud.google.com 에서 새 프로젝트를 만듭니다. 이름은 예를 들어 `exam-login`으로 합니다.
2. **Google Auth Platform**(이전 이름 'OAuth 동의 화면')에서 다음을 설정합니다.
   - 앱 이름: `○○중 평가`, 지원 이메일: 본인 Gmail, 대상: **외부(External)**
   - **대상(Audience) → 앱 게시(Publish app)** 를 눌러 '프로덕션'으로 바꿉니다.
     '테스트' 상태로 두면 등록한 테스트 사용자만 로그인할 수 있습니다.
     이메일과 프로필만 쓰기 때문에 구글 심사는 필요 없습니다.
3. **클라이언트(Clients) → 클라이언트 만들기**에서 다음을 넣습니다.
   - 유형: **웹 애플리케이션**
   - 승인된 리디렉션 URI: `https://<프로젝트ID>.supabase.co/auth/v1/callback`
     (이 주소는 Supabase의 Authentication → Providers → Google 화면에 그대로 나옵니다)
4. 만들어진 **클라이언트 ID**와 **클라이언트 보안 비밀번호**를 복사합니다.

### 3. Supabase에 구글 로그인 연결
1. Supabase에서 **Authentication → Sign In / Providers → Google**로 갑니다.
2. Enable을 켜고, 위에서 복사한 ID와 비밀번호를 붙여 넣은 뒤 Save를 누릅니다.

### 4. 화면을 GitHub Pages에 올리기
1. `docs/config.js`에 두 값을 채웁니다. 위치는 Supabase **Project Settings → API Keys**입니다.
   - `SUPABASE_URL`: `https://<프로젝트ID>.supabase.co`
   - `SUPABASE_ANON_KEY`: **anon public** 키 (또는 publishable 키)
   - ⚠ `service_role` / `secret` 키는 **절대** 넣지 마세요.
2. GitHub에서 저장소를 만듭니다. 예: `exam`, **Public**.
3. **Add file → Upload files**에 `exam-system` 폴더 안의 내용(README.md, supabase, docs)을 통째로 끌어다 놓고 Commit을 누릅니다.
4. **Settings → Pages**에서 Branch `main` / `/docs`를 선택하고 Save를 누릅니다. 1~2분 뒤 주소가 생깁니다.
   - 학생용: `https://<아이디>.github.io/exam/`
   - 교사용: `https://<아이디>.github.io/exam/teacher.html`

### 5. 로그인 후 돌아올 주소 등록
1. Supabase에서 **Authentication → URL Configuration**으로 갑니다.
2. **Site URL**에 `https://<아이디>.github.io/exam/`를 넣습니다.
3. **Redirect URLs**에 `https://<아이디>.github.io/exam/**`를 추가합니다.

### 6. 확인
1. 교사 주소로 들어가 본인 Gmail로 로그인합니다. **시험 · 문항** 탭이 보이면 성공입니다.
2. 다른 구글 계정(또는 시크릿 창)으로 학생 주소에 들어가 등록해 봅니다. 교사 화면 **학생 승인** 탭에 나타나면 끝입니다.

## 운영 순서

1. **시험 만들기:** 교사 화면에서 **+ 새 시험**을 누르고 이름을 정합니다.
2. **문항 넣기:** 구글 시트에 아래 순서로 작성하고, 표를 복사해 **문항 붙여넣기** 칸에 붙여 넣은 뒤 **문항 교체**를 누릅니다.

   | 번호 | 유형 | 문제 | 보기1 | 보기2 | 보기3 | 보기4 | 보기5 | 정답 | 배점 |
   |---|---|---|---|---|---|---|---|---|---|
   | 1 | 객관식 | 다음 중 소수는? | 4 | 6 | 7 | 9 | | 3 | 2 |
   | 2 | 객관식 | 짝수를 고르시오. | 1 | 2 | 3 | 4 | | 2\|4 | 2 |
   | 3 | 단답형 | 대한민국의 수도는? | | | | | | 서울\|서울특별시 | 3 |

   - 객관식 정답은 **보기 번호**입니다. 복수정답은 `2|4`처럼 씁니다.
   - 단답형은 `|`로 여러 답을 허용할 수 있고, 띄어쓰기와 대소문자는 무시하고 채점합니다.
3. **설정:** 시작·마감 시각, 응시 횟수, 문항·보기 섞기, 제출 후 학생에게 보여줄 내용(점수 / 점수+O·X / 비공개)을 정한 뒤 **학생에게 공개**를 체크하고 저장합니다.
4. **학생 안내:** 학생 주소 하나만 QR이나 클래스룸으로 안내합니다. 학생은 처음 한 번 반·번호를 등록합니다.
5. **승인:** **학생 승인** 탭에서 반·번호와 이메일을 확인하고 승인합니다. 잘못 등록한 학생은 삭제하면 다시 등록할 수 있습니다.
6. **결과:** **결과** 탭에서 점수, 문항별 O/X, 문항별 정답률을 보고 **CSV 내려받기**로 엑셀에 저장합니다.

### 구글 사이트(교과사이트)에 넣을 때
구글 로그인 화면은 보안상 **다른 사이트 안(iframe)에서 열리지 않습니다.**
그래서 구글 사이트에는 '코드 삽입'이나 'URL 삽입' 대신 **'삽입 → 버튼'으로 학생 주소 링크**를 거세요. 새 탭에서 열립니다.

## 꼭 알아 둘 점

**무료 요금제 일시정지**
- Supabase 무료 프로젝트는 **7일간 사용이 없으면 일시정지**됩니다.
- **시험 전날 Supabase 대시보드에 들어가** 일시정지 상태라면 **Restore**를 누르세요. 몇 분 걸립니다. 데이터는 그대로 있습니다.
- 용량(DB 500MB, 월 사용자 5만 명)은 학교 단위로는 충분합니다.

**보안 범위**

| 막아 주는 것 | 막지 못하는 것 (교실에서 관리) |
|---|---|
| 정답 엿보기 (정답이 학생 기기에 전송되지 않음) | 다른 사람이 대신 풀기, 옆 사람 보기 |
| 다른 학생 결과 보기, 결과 조작 | 문제 화면 캡처·공유 |
| 횟수 초과 재응시, 마감 후 제출 (2분 유예) | 다른 탭에서 검색하기 |

**개인정보**
- 저장하는 정보는 **구글 이메일, 반, 번호, 답안, 점수**입니다. 이름은 받지 않습니다.
- 개인 계정 방식이므로 학교 지침에 맞춰 학생에게 수집 항목을 안내하세요.
- 학기가 끝나면 아래 SQL로 지우세요.

**응시 중 끊김**
- 작성 중인 답은 학생 기기에 자동 임시 저장됩니다. 새로고침이나 재로그인 후 다시 **응시하기**를 누르면 답이 복원됩니다. 단, 같은 기기와 같은 회차일 때만입니다.

## 자주 쓰는 SQL (Supabase → SQL Editor)

```sql
-- 교사 추가 (동료 선생님)
insert into teachers (email) values ('colleague@gmail.com');

-- 학기 말 정리: 제출 기록과 학생 등록 전체 삭제 (시험·문항은 남김)
delete from submissions;
delete from students;

-- 학생 로그인 계정까지 완전히 삭제하려면 Authentication → Users 에서 삭제
```

## 문제 해결
- **로그인 후 다시 로그인 화면으로 돌아옴:** 5단계 Redirect URLs의 주소가 실제 주소와 같은지 확인하세요. 끝의 `/**`도 필요합니다.
- **"교사 계정이 아닙니다":** `teachers` 테이블에 로그인한 Gmail이 소문자로 들어 있는지 확인하세요.
- **"Unsupported provider" / 구글 오류 화면:** 3단계 Google 연결, 2단계 리디렉션 URI, 앱 게시(프로덕션) 상태를 확인하세요.
- **학생이 "이미 다른 계정으로 등록된 번호":** 학생이 다른 계정으로 이미 등록했거나 다른 학생이 잘못 등록한 경우입니다. 교사 화면에서 해당 행을 삭제하면 됩니다.
